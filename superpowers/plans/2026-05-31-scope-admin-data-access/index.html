    Scope Admin (Superuser) Data Access — Implementation Plan¶

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task. Steps use checkbox (- [ ]) syntax.

    Goal: Remove the blanket is_superuser bypass from the data-permission layer so admins are authorized over user data identically to normal users, retaining only (a) a narrow structural-write break-glass exception and (b) existing superuser-gated config mutations.

    Architecture: Strip ~15 if user.is_superuser: return self.all()/True short-circuits across managers, querysets, query optimizers, the permission-utility layer, and the GraphQL permission mixin. Keep the structural-write exception inside AnnotationManager.user_can/RelationshipManager.user_can. Rework badge-awarding to authorize-then-unfiltered-lookup so removing the UserProfileManager bypass doesn't break it. Update the invariant suite + per-area permission tests to the new contract, then rewrite the guide.

    Tech Stack: Django 4.x, django-guardian, pytest/pytest-xdist, Graphene.

    Test command (scoped — do NOT run full 30-min suite): 

    docker compose -f test.yml run --rm django pytest opencontractserver/tests/permissioning -n 4 --dist loadscope
    Plus the named query-optimizer/badge test modules as they're touched.

    File Structure¶

    Production: - opencontractserver/shared/Managers.py — base visibility + annotation/relationship/note managers - opencontractserver/shared/QuerySets.py — document/annotation/note/feedback/tree/permission querysets - opencontractserver/users/models.py — UserProfileManager - opencontractserver/utils/permissioning.py — _default_user_can, get_users_permissions_for_obj - config/graphql/permissioning/permission_annotator/mixins.py — resolve_my_permissions - opencontractserver/annotations/query_optimizer.py — _compute_effective_permissions - opencontractserver/extracts/query_optimizer.py — metadata optimizer - opencontractserver/documents/query_optimizer.py — document-actions optimizer (+ extract/analysis/relationship optimizer superuser branches surfaced by the sweep) - config/graphql/badge_mutations.py + opencontractserver/badges/services/badge_service.py — badge awarding/visibility

    Tests: the invariant suite + ~24 permission/query-optimizer/badge modules (Task 7).

    Docs: docs/permissioning/consolidated_permissioning_guide.md, CHANGELOG.md.

    Task 1: Encode the new contract in the invariant suite (failing tests first)¶

    Files: - Modify: opencontractserver/tests/permissioning/test_authorization_invariants.py

    • Step 1: Rewrite _UserCanInvariantsMixin.test_superuser_bypass_all_permissions → data-parity. Replace the "superuser passes every permission on every instance" loop with: a superuser with no grants is denied write/permission perms on instances it does not own and is not shared on, and is denied READ on non-public instances it does not own. Rename to test_superuser_with_no_grants_has_no_blanket_access.
    def test_superuser_with_no_grants_has_no_blanket_access(self):
    """A superuser without grants is authorized like a stranger (data parity)."""
    for instance in self._matrix_instances:
        is_public = getattr(instance, "is_public", False)
        owns = getattr(instance, "creator_id", None) == self._superuser.pk
        if is_public or owns:
            continue
        for perm in (PermissionTypes.UPDATE, PermissionTypes.DELETE,
                     PermissionTypes.PERMISSION):
            self.assertFalse(
                self.model_cls.objects.user_can(self._superuser, instance, perm),
                f"superuser got blanket {perm} on {self.model_cls.__name__} "
                f"pk={instance.pk} — data bypass leak!",
            )

    • Step 2: Keep structural exception tests. Leave test_structural_*_are_read_only_for_non_superuser asserting the superuser CAN UPDATE a structural item (the retained break-glass). Add to each a parity assertion that a non-structural instance the superuser cannot otherwise access is NOT writable by them (already covered by Step 1 mixin; only add if the structural subclass overrides the mixin test).

    • Step 3: Rewrite CorpusAuthorizationInvariantsTestCase superuser tests. test_superuser_bypass_all_permissions and test_superuser_bypass_via_corpus_delegate → assert a no-grant superuser is denied UPDATE/DELETE/PERMISSION on private_corpus (and folder), but still gets READ on public_corpus. Add a positive case: grant the superuser READ on private_corpus via set_permissions_for_obj_to_user and assert READ now passes — proving normal-user semantics.

    • Step 4: Run the suite — expect FAIL (production still bypasses): 

      docker compose -f test.yml run --rm django pytest opencontractserver/tests/permissioning/test_authorization_invariants.py -n 4 --dist loadscope

    Task 7: Sweep the wider permission/optimizer/badge test suite¶

Where a test's intent was "prove blanket access," either delete it or invert it to prove parity. Add the explicit parity/positive-grant cases noted in the spec.

    Files (each is its own commit-sized unit): - [ ] test_base_model_permissions.py — test_visible_to_user_superuser_sees_everything → no-grant superuser sees only public/own/shared; test_distinct_not_applied_for_superuser → distinct now IS applied (rename/adjust). - [ ] test_permissioned_querysets.py — test_superuser_sees_all, test_superuser_non_lightweight_skips_user_perm_prefetch → invert to parity + prefetch-now-applied. - [ ] test_get_for_user_or_none.py — test_superuser_sees_everything → no-grant superuser cannot fetch private stranger object. - [ ] test_creator_based_permissions.py — test_superuser_gets_all_permissions_on_annotation_label, test_user_can_superuser, test_superuser_gets_all_guardian_permissions, test_superuser_has_each_permission_type → computed-like-normal-user. - [ ] test_comment_permission.py — test_superuser_has_comment_permission → only with READ access. - [ ] test_corpus_visibility.py — test_superuser_can_change_any_corpus_visibility → only corpora the admin can UPDATE as a normal user. - [ ] test_feedback_mutations.py — test_superuser_can_always_provide_feedback → only on visible annotations. - [ ] test_user_visibility.py — test_superuser_can_see_all_active_users → sees only public/own/shared-corpus profiles. - [ ] test_badge_visibility.py — test_superuser_sees_all_badges → sees awards per normal profile privacy. - [ ] test_badges.py — test_non_superuser_cannot_award_to_private_profile_recipient re-meaning: authorized awarder (superuser/corpus owner) CAN award to a private recipient via unfiltered lookup; unauthorized caller rejected at the authorization gate.
