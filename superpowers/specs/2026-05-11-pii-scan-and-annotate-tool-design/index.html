    PII Scan & Auto-Annotate Tool — Design¶

    Status: Draft Date: 2026-05-11 Author: scrudato

    Goal¶

    Add an agent tool that scans an OpenContracts document for sensitive information using the privacy-filter microservice and creates one labeled annotation per detection.

    • PDFs → token-level annotations via PlasmaPDF (TOKEN_LABEL).
    • Plain text → character-span annotations (SPAN_LABEL).
    • Both share the agent-tool contract used by add_annotations_from_exact_strings (sync core + a-prefixed async wrapper, requires_approval=True, requires_write_permission=True).

    Non-Goals¶

    • Auto-trigger on corpus ingest. The tool already accepts corpus_action_id, so wiring is a one-liner later but is not part of this spec.
    • Redaction/anonymization (replacing PII with placeholders).
    • A separate "scan a raw text snippet" tool (no document_id). Trivial to add later by exposing the chunker directly.
    • Dedicated PII-only UI; existing annotation chrome handles labels and filters.

    External Dependency: privacy-filter¶

    A stateless FastAPI service with one production endpoint:

    • POST /v1/detect, X-API-Key header, JSON {"text": "..."}.
    • Response: {"detections": [{"entity_group", "score", "word", "start", "end"}, ...]}.
    • /healthz (liveness) and /readyz (503 until model loaded).
    • Default MAX_INPUT_CHARS = 50,000.
    • Entity groups (8): private_email, phone_number, person_name, address, account_number, url, date, secret.

    Components¶

    1. Docker service¶

    Add privacy_filter to local.yml and production.yml only — not to test.yml (image is large; tests mock the HTTP client).

    # local.yml (and analogous in production.yml)
services:
  privacy_filter:
    image: ghcr.io/open-source-legal/privacy-filter:latest
    container_name: opencontracts_local_privacy_filter
    environment:
      API_KEYS: ${PRIVACY_FILTER_API_KEY:-dev-only-not-secret}
      MAX_INPUT_CHARS: "50000"
      CORS_ORIGINS: "" # not browser-facing
    restart: unless-stopped
    # NOT published to host; reachable only on the internal docker network

    Add the service name to the depends_on block of django and celeryworker so it boots with the stack.

    2. Settings + env config¶

    .envs/.local/.django adds:

    PRIVACY_FILTER_URL=http://privacy_filter:8000
PRIVACY_FILTER_API_KEY=dev-only-not-secret

    config/settings/base.py reads them:

    PRIVACY_FILTER_URL = env("PRIVACY_FILTER_URL", default="")
PRIVACY_FILTER_API_KEY = env("PRIVACY_FILTER_API_KEY", default="")
PRIVACY_FILTER_TIMEOUT_SECONDS = env.int("PRIVACY_FILTER_TIMEOUT_SECONDS", default=30)

    If PRIVACY_FILTER_URL is empty the tool returns a deterministic error string to the LLM ("Privacy-filter service is not configured for this deployment.") rather than raising.

    3. HTTP client¶

    opencontractserver/llms/tools/core_tools/_privacy_filter_client.py

    class Detection(TypedDict):
    entity_group: str
    score: float
    start: int          # offset relative to the `text` arg passed to adetect_pii
    end: int
    text: str           # canonical text[start:end], not the model's `word` field

async def adetect_pii(text: str) -> list[Detection]: ...

    Async-only — mirrors the existing web_search_tools.py pattern (httpx.AsyncClient). Callers in sync DB contexts should not need it; the tool's async entrypoint awaits this directly before delegating DB work to _db_sync_to_async.

    Responsibilities:

    • Chunking: CHUNK_SIZE = 40_000, CHUNK_OVERLAP = 500. Iterate chunk_start = 0, 39_500, 79_000, ... until past len(text).
    • Per-chunk POST /v1/detect with X-API-Key using httpx.AsyncClient with the configured timeout.
    • Remap detection offsets within the chunk back to indices into text: start_in_text = chunk_start + det["start"].
    • Deduplicate across overlap by (start, end, entity_group).
    • Re-derive each detection's text from the input string (do not trust the model's word field — fewer surprises with whitespace and casing).
    • On non-2xx response, raise RuntimeError with status + first 200 chars of body so the agent-tool wrapper can return it as an error string.

    4. Tool function¶

    opencontractserver/llms/tools/core_tools/pii.py

    ENTITY_GROUP_LABELS: dict[str, tuple[str, str, str]] = {
    "private_email":   ("PII: Email",          "#1f77b4", "mail"),
    "phone_number":    ("PII: Phone",          "#ff7f0e", "phone"),
    "person_name":     ("PII: Person Name",    "#2ca02c", "user"),
    "address":         ("PII: Address",        "#d62728", "home"),
    "account_number":  ("PII: Account Number", "#9467bd", "credit card"),
    "url":             ("PII: URL",            "#8c564b", "linkify"),
    "date":            ("PII: Date",           "#e377c2", "calendar"),
    "secret":          ("PII: Secret",         "#7f7f7f", "key"),
}

async def ascan_and_annotate_pii(
    *,
    # context-injected
    document_id: int,
    corpus_id: int,
    creator_id: int,
    corpus_action_id: int | None = None,
    # agent-controllable
    min_score: float = 0.5,
    entity_groups: list[str] | None = None,
    dry_run: bool = False,
    start_char: int | None = None,
    end_char: int | None = None,
) -> dict:
    # 1. Load doc + doc_text (sync DB) via _db_sync_to_async helper.
    # 2. await adetect_pii(slice)  — async network I/O.
    # 3. Persist annotations (sync DB) via _db_sync_to_async helper.

    Splitting (1) and (3) into _db_sync_to_async-wrapped helpers keeps the async entrypoint free of SynchronousOnlyOperation risk while letting the network round-trip stay native-async, matching web_search_tools.py.

    No sync public entrypoint is exposed; the tool registry only references the async name (ascan_and_annotate_pii).

    Return shape:

    {
  "document_id": int,
  "scanned_chars": int,
  "detection_count": int,
  "by_entity_group": {"private_email": 3, "phone_number": 1, ...},
  "annotation_ids": list[int],          # [] when dry_run
  "detections": list[dict],             # populated only when dry_run
}

    Each entry in detections (dry_run only):

    {"entity_group": str, "score": float, "start": int, "end": int, "text": str}

    5. Data flow¶

    ascan_and_annotate_pii(doc_id, knobs)
   │
   ├─ resolve doc + corpus, verify linkage (same as existing tool)
   ├─ load doc_text:
   │     PDF  → expand_pawls_pages + build_translation_layer; pdf_layer.doc_text
   │     text → doc.txt_extract_file.read()
   │     other → ValueError("Unsupported file_type ...")
   │
   ├─ slice = doc_text[start_char or 0 : end_char or len]
   │   (record `slice_offset = start_char or 0`)
   │
   ├─ await adetect_pii(slice) → list[Detection]  (offsets relative to slice)
   ├─ shift each offset by slice_offset → global doc_text offsets
   ├─ filter: score >= min_score AND (entity_groups is None or group in set)
   │
   ├─ if dry_run: return {detections: [...], annotation_ids: []}
   │
   └─ atomic transaction:
        for det in detections:
            label_text, color, icon = ENTITY_GROUP_LABELS[det.entity_group]
            label = corpus.ensure_label_and_labelset(
                label_text=label_text, label_type=<TOKEN_LABEL|SPAN_LABEL>,
                color=color, icon=icon, creator_id=creator_id,
            )
            PDF:  span = TextSpan(uuid4, start=g_start, end=g_end, text=doc_text[g_start:g_end])
                  oc  = pdf_layer.create_opencontract_annotation_from_span(SpanAnnotation(span, label.text))
                  Annotation(... raw_text=oc["rawText"], page=oc["page"], json=oc["annotation_json"],
                             annotation_type=TOKEN_LABEL, corpus_action_id=corpus_action_id, ...).save()
            text: Annotation(... raw_text=doc_text[g_start:g_end], page=1,
                             json={"start": g_start, "end": g_end},
                             annotation_type=SPAN_LABEL, corpus_action_id=corpus_action_id, ...).save()
            append id to annotation_ids
        return {by_entity_group, detection_count, annotation_ids, ...}

    7. Error handling¶

    Failure Handling
    PRIVACY_FILTER_URL empty Return error string to LLM via existing fault-tolerance wrapper.
    HTTP transport / 5xx / /readyz failure RuntimeError → wrapper returns error string to LLM.
    Document not in corpus / unsupported file_type ValueError (mirrors add_annotations_from_exact_strings).
    Detection offset out of bounds after remap Skip, log WARNING, continue.
    start_char/end_char out of range Clamp to [0, len(doc_text)]; if start >= end, return zero detections.
    Permission failures (read-only user) Already handled upstream by the agent-tool framework.

    Testing strategy¶

    All tests mock the privacy-filter HTTP client — no live container.

    opencontractserver/tests/test_pii_scan_tool.py (new):

    1. PDF happy path — fixture PDF + PAWLs, mocked detections at known offsets; assert 1 annotation per detection, TOKEN_LABEL, correct annotation_label, raw_text, json["annotation_json"] non-empty.
    2. Text happy path — .txt document, assert SPAN_LABEL with json == {"start": s, "end": e}.
    3. Dry-run — dry_run=True ⇒ no Annotation rows created, detections populated, annotation_ids == [].
    4. Score threshold — min_score=0.9 filters out a 0.7 detection.
    5. Entity-group allowlist — entity_groups=["private_email"] skips phone_number detections.
    6. Char-range scope — start_char/end_char slice; offsets in returned annotations are global (not slice-relative).
    7. Chunk-boundary dedup — client receives a 41,000-char text, two chunks overlap on a person_name detection; assert exactly one annotation.
    8. Unsupported file_type — application/png raises ValueError.
    9. Service unconfigured — PRIVACY_FILTER_URL="" returns an error string, no exception bubbles to the test runner.
    10. Permission filtering — read-only user on the corpus has the tool filtered out of the resolved tool set (uses existing test helper for tool-set resolution).

    Client-only unit tests in test_privacy_filter_client.py:

    • Chunking math: 0 / 1 / 2 / 3 chunks for varying input lengths.
    • Offset remap: detection at chunk-local index i of chunk N appears at global index N * (CHUNK_SIZE - CHUNK_OVERLAP) + i.
    • Dedup: identical (start, end, group) triple from two chunks → one entry.
    • 5xx response → RuntimeError.
