    Design: Stop sending empty Authorization header from Apollo (issue #1431)¶

    Date: 2026-05-01 Issue: #1431 Follow-up: #1432 — backend CSRF hardening (out of scope here) Branch: claude/fix-empty-auth-header-1431

    Summary¶

    Production logs show a steady stream of 403 Forbidden (CSRF token missing.) on POST /graphql/. Root cause is purely client-side: frontend/src/index.tsx always sets Authorization: token ? "Bearer …" : "", and the backend's conditional_csrf_exempt (config/graphql/security.py:43) treats the empty string as falsy and falls into the session+CSRF branch. The SPA has no CSRF flow (Bearer-only by design), so the request 403s.

    This spec fixes the frontend at the Apollo transport layer and removes a related noisy log in Auth0JWTSettings.__getattr__. Broader backend hardening is tracked separately in #1432.

    Problem¶

    1. Empty Authorization: when authToken() returns "" (Auth0 still loading, refresh failed, expired token, logged out), the Authorization header is sent as "". The backend's session/CSRF path rejects every such request.
    2. Startup race: <ApolloProvider> is mounted above <AuthGate> in frontend/src/index.tsx. AuthGate gates child rendering until Auth0 finishes, but Apollo itself is alive earlier. Any code path that issues a query during the gating window reaches the network without a token.
    3. Log noise: Auth0JWTSettings.__getattr__ (config/graphql_auth0_auth/settings.py:73-79) logs unknown-attribute access at ERROR. Python uses unknown-attr probes routinely (hasattr, pickle, deepcopy, _user_settings lookup, dunder methods); these are normal AttributeError control flow, not errors.

    Goals¶

    • No Authorization: "" ever leaves the SPA.
    • No GraphQL operation reaches the network before AuthGate has resolved auth state (token or anonymous).
    • Mid-session token expiry behavior unchanged (errorLink already handles 401/403 → reload → AuthGate re-run).
    • Auth0JWTSettings no longer ERROR-logs normal AttributeError flow.

    Non-Goals¶

    • Adding CSRF token plumbing to the SPA (it remains Bearer-only).
    • Modifying conditional_csrf_exempt semantics — see #1432.
    • Changing AuthGate's UX choices around refresh failure (still falls back to anonymous).
    • Forcing redirect-to-login on token absence (existing UX is anonymous browsing).

    Approach¶

    Replace the synchronous ApolloLink in frontend/src/index.tsx with a setContext-based async link that:

    1. Awaits authInitCompleteVar before computing headers, using onNextChange (event-driven, not polled).
    2. Conditionally spreads Authorization: Bearer <token> only when authToken() is non-empty.

    Extract the link into its own module so it can be unit-tested in isolation.

    Architecture¶

    Caller (component / hook)
        │
        ▼
ApolloClient.query / mutate
        │
        ▼
errorLink ── setContext(authLink) ── httpLink ──► /graphql/
              │
              ├─ if !authInitCompleteVar(): await onNextChange(true)
              ├─ token = authToken()
              └─ headers = { ...headers, ...(token ? { Authorization: `Bearer ${token}` } : {}) }

    Single choke point — every operation passes through authLink. AuthGate continues to gate React rendering for a smooth UX; the link gates the transport for correctness.

    Components¶

    1. frontend/src/graphql/authLink.ts (new)¶

    import { setContext } from "@apollo/client/link/context";
import { authToken, authInitCompleteVar } from "./cache";

/**
 * Resolves once auth initialization has completed (token resolved or anonymous).
 * Uses Apollo's reactive-var onNextChange so the wait is event-driven.
 */
export function waitForAuthInit(): Promise<void> {
  if (authInitCompleteVar()) return Promise.resolve();
  return new Promise<void>((resolve) => {
    const unsubscribe = authInitCompleteVar.onNextChange((value) => {
      if (value) {
        unsubscribe();
        resolve();
      }
    });
  });
}

/**
 * Apollo auth link.
 *
 * Defers operations until AuthGate has finished initializing, then attaches
 * a Bearer token if one is available. Sending an empty Authorization header
 * trips the backend's conditional CSRF check and produces 403s, so we omit
 * the header entirely when no token is present.
 */
export const authLink = setContext(async (_operation, { headers }) => {
  await waitForAuthInit();
  const token = authToken();
  return {
    headers: {
      ...headers,
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
    },
  };
});

    2. frontend/src/index.tsx (edit)¶

    Remove the inline authLink (lines 36-48). Replace with import { authLink } from "./graphql/authLink";. The ApolloLink.from([errorLink, authLink, httpLink]) composition is unchanged.

    3. config/graphql_auth0_auth/settings.py (edit)¶

    In Auth0JWTSettings.__getattr__, drop the logger.error(...) line. The raise AttributeError(...) stays. The DEBUG log at the top of the method also stays — it's useful for diagnostics and only fires at DEBUG level.

    Before: 

    def __getattr__(self, attr):
    logger.debug(f"Auth0JWTSettings.__getattr__() - Accessing setting: {attr}")
    if attr not in self.defaults:
        logger.error(
            f"Auth0JWTSettings.__getattr__() - Invalid setting requested: {attr}"
        )
        raise AttributeError(f"Invalid setting: `{attr}`")
    ...

    After: 

    def __getattr__(self, attr):
    logger.debug(f"Auth0JWTSettings.__getattr__() - Accessing setting: {attr}")
    if attr not in self.defaults:
        raise AttributeError(f"Invalid setting: `{attr}`")
    ...

    Data flow¶

    Authenticated user, app boot (Auth0): 1. <ApolloProvider> mounts; authInitCompleteVar is false. 2. Component fires a query → setContext runs → awaits onNextChange. 3. <AuthGate> calls getAccessTokenSilently(), sets authToken(token), sets authInitCompleteVar(true). 4. setContext resolves, attaches Authorization: Bearer <token>, request goes to /graphql/.

    Anonymous user (Auth0, no session): 1. Same as above through step 2. 2. AuthGate's silent-token call fails → sets authToken(""), authInitCompleteVar(true). 3. setContext resolves, omits Authorization, request goes to /graphql/ as anonymous. Public queries succeed; protected ones get a clean auth error handled by errorLink.

    Non-Auth0 mode: 1. <AuthGate> immediately sets authInitCompleteVar(true) (AuthGate.tsx:92-101). 2. setContext resolves immediately on every operation. If a Bearer token has been set via the login form, it's attached; otherwise the request is anonymous.

    Mid-session token expiry: Unchanged. Stale Bearer goes out, backend returns 401/403, errorLink reloads the page, AuthGate re-runs.

    Error handling¶

    Scenario Behavior
    AuthGate hangs forever getAccessTokenSilently has a 10s timeout (AuthGate.tsx:279); on timeout AuthGate flips authInitCompleteVar(true) with empty token. Link unblocks.
    onNextChange never fires Cannot happen given the above timeout, but worst case the user sees a hung query — same UX as today's race. No regression.
    Token expires after init Stale header sent → backend 401/403 → errorLink reloads → AuthGate refreshes. Existing flow.
    User logs out authToken("") set synchronously; next operation omits Authorization and is treated as anonymous.
    Apollo cache reads (no network) Don't traverse the link. Unaffected.

    Testing¶

    New unit tests — frontend/src/graphql/authLink.test.ts (Vitest)¶

    Drive the link with execute() from @apollo/client/core composed with a terminating ApolloLink stub that captures the operation's headers. Manipulate authToken / authInitCompleteVar directly (they're exported from cache.ts).

    1. Empty token, init complete → terminating link sees no Authorization key in headers.
    2. Valid token, init complete → terminating link sees Authorization: Bearer <token>.
    3. Init not complete → terminating link is not invoked; after authInitCompleteVar(true), it is invoked with correct headers.
    4. Token set but init not complete → still gated on init flag (proves the gate is on init completion, not token presence).
    5. waitForAuthInit() resolves synchronously when init is already complete (guards against subscription leaks).

    New backend test — extend or add an Auth0JWTSettings test¶

    Use assertLogs to verify the unknown-attr branch: - Accessing auth0_settings.does_not_exist raises AttributeError. - The captured log records contain no ERROR-level entry from config.graphql_auth0_auth.settings. - A known attribute (e.g. AUTH0_DOMAIN) still works.

    Locate existing test file via grep -r "Auth0JWTSettings\|auth0_settings" opencontractserver/tests/. If none, add opencontractserver/tests/test_auth0_settings.py.

    Manual smoke test¶

    1. With Auth0 enabled, hard-reload the SPA while logged in. Watch Network tab — every POST /graphql/ should carry Authorization: Bearer … and 200 OK.
    2. Log out. Observe subsequent POST /graphql/ requests carry no Authorization header and either 200 (public) or return a clean auth error (protected).
    3. With Auth0 disabled, boot the app — no requests should send Authorization: "".
    4. Tail docker compose -f local.yml logs django and confirm Forbidden (CSRF token missing.) no longer fires during normal browsing.

    Rollout¶

    • Single PR targeting main.
    • No migrations.
    • No env-var changes.
    • No feature flag — fix is strictly safer than current behavior.

    Risks¶

    • onNextChange semantics: Apollo's reactive-var subscription fires on the next change, not the current value. The waitForAuthInit() helper checks the current value first to avoid waiting forever if init completed before the subscription was set up. This is covered by test case 5.
    • @apollo/client/link/context: standard Apollo subpackage; already a transitive dep of @apollo/client. No new package install.
    • Behavior in tests that mount components without AuthGate: existing test wrappers set authInitCompleteVar(true) (or its equivalent) — verify a couple of representative wrappers still set this var. If any wrapper relies on the old synchronous link behavior (operations firing before init), it will hang. Mitigation: a quick grep + spot-check during implementation; if anything breaks, the fix is one line in the wrapper.

    Out of scope¶

    • Backend hardening of conditional_csrf_exempt (#1432).
    • Migrating <ApolloProvider> below <AuthGate> in the React tree. Theoretically tidier but invasive — the link-level gate achieves the same outcome with much less surgery.
    • Refresh-token-from-link logic. Duplicates AuthGate; conflicts with the existing "fall back to anonymous" UX.
