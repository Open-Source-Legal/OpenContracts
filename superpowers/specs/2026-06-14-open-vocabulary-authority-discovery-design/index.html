    Open-Vocabulary Authority Discovery & Recursive Graph Enrichment — Design¶

    Status: draft for review (2026-06-14). Successor design to the reference enrichment engine (docs/superpowers/specs/2026-06-09-corpus-reference-enrichment-agent-design.md). Builds directly on the shipped engine in opencontractserver/enrichment/.

    1. Problem¶

    The shipped enrichment engine is closed-vocabulary. ReferenceExtractor (opencontractserver/enrichment/extractor.py) only fires on authorities whose alias is in a registry: the static AUTHORITY_PREFIX map (constants.py:35 — seven bodies of law: DGCL, Securities Act, Exchange Act, IRC, ICA, IAA, plus bare SEC rules) merged with aliases that bootstrapped authority corpora stamp into Document.custom_meta.authority_aliases (authorities.py:authority_alias_registry).

    The consequence for less-common legal regimes is structural, not incidental:

    • A citation to an authority we have no registered alias for is never detected. "Texas Business Organizations Code § 21.401", "40 C.F.R. § 261.4", "San Francisco Police Code art. 38", "the Bank Holding Company Act" — all invisible. wanted_authorities() ranks the EXTERNAL refs the extractor did emit; it cannot surface an authority the extractor never recognized.
    • There is no external ingestion. Authorities are hand-seeded JSON (demo/authority_seeds/*.json) materialized through bootstrap_authority_corpus. Locating and importing a new body of law is a manual, code-and-curate task.

    So "as we traverse our graph and enrich, find the weird ones — authorities we don't know exist a priori, and don't know where to find" is blocked at the detection layer, long before location or ingestion. It also conflates two distinct problems and adds a third opportunity:

    • A — Discovery (open-vocabulary detection): recognize that a span is a citation to some authority, even one with no registered alias. A recall problem the registry regex cannot solve.
    • B — Location & ingestion (unknown source): given a recognized-but- unknown authority, find where its text lives and import it — without a hardcoded per-source integration.
    • C — Recursion (the graph is the crawler): every authority we ingest contains its own citations (statutes cross-reference; regulations cite enabling statutes; cases cite statutes). wanted_authorities is really a frontier, and enrichment is a bounded breadth-first crawl over legal-authority space.

    2. Goals & non-goals¶

    Goals

    1. Detect citations to authorities outside the registry (federal, state, local, administrative, obscure agencies), classified by jurisdiction and authority type, with calibrated confidence.
    2. Triage detected-but-unhosted authorities into a ranked frontier.
    3. Route each frontier item to a pluggable source provider — public-domain government sources, plus an agentic web-locate fallback for the truly unknown.
    4. Gate every agentic / low-confidence ingest behind verification + a license check; never silently drop an authority we couldn't compliantly fetch — make it a visible terminal state with its candidate sources attached.
    5. Expand the frontier recursively as ingested authorities reveal their own citations, under explicit depth / budget / demand bounds.
    6. Reuse the shipped ingestion + relink machinery (bootstrap_authority_corpus, relink_corpora_for_keys) verbatim — the new work is detection, routing, and recursion, not re-plumbing persistence.

    Non-goals (deliberately deferred)

    • Full case-law citation graphs. Case law (reporters, parallel cites, pincites, subsequent history) is a different modeling problem. CourtListenerProvider is stubbed behind a feature flag, off by default.
    • Authority versioning / re-pointing. The known stale-RESOLVED-reference gap (docs/architecture/reference-web-versioning.md) is out of scope; this design must not widen it. New ingests use the existing version-up path and inherit its current semantics.
    • Definition-to-usage linking for defined terms — unchanged from today.
    • Replacing Tier-1 detection. The registry path stays the trusted fast path; open-vocabulary detection is strictly additive and opt-in.

    3. Architecture overview¶

                             ┌──────────────────────────────────────────┐
   document text  ─────▶ │  DETECTION  (extractor, layered)          │
                         │   Tier 1  registry grammars   (trusted)   │
                         │   Tier 2a generic shape grammars (cheap)  │
                         │   Tier 2b LLM extraction pass   (recall)  │
                         │   → reconcile / dedupe / confidence       │
                         └───────────────┬──────────────────────────┘
                                         │ Candidates (+ jurisdiction,
                                         │              authority_type)
                                         ▼
                         ┌──────────────────────────────────────────┐
   resolver + writer ──▶ │  PERSIST   CorpusReference (EXTERNAL)     │
   (unchanged shape)     │            + AuthorityNamespace upsert    │
                         └───────────────┬──────────────────────────┘
                                         ▼
                         ┌──────────────────────────────────────────┐
                         │  FRONTIER  AuthorityFrontier (the queue)  │
                         │   rank = demand × confidence − depth      │
                         └───────────────┬──────────────────────────┘
                                         ▼
                         ┌──────────────────────────────────────────┐
                         │  ROUTE     provider registry              │
                         │   USCode · CFR · FedRegister · StateCode  │
                         │   · CourtListener(off) · AgenticWeb(*)    │
                         └───────────────┬──────────────────────────┘
                                         ▼
                         ┌──────────────────────────────────────────┐
                         │  GATE      verify(citation,text) + license│
                         │   pass+trusted → ingest                   │
                         │   else → BLOCKED_LICENSE / UNLOCATED /    │
                         │          PENDING_APPROVAL  (all visible)  │
                         └───────────────┬──────────────────────────┘
                                         ▼  AuthoritySection[]
                         ┌──────────────────────────────────────────┐
                         │  INGEST    bootstrap_authority_corpus()   │  ← REUSED
                         │            → relink_corpora_for_keys()    │  ← REUSED
                         │            → re-extract new authority doc │
                         └───────────────┬──────────────────────────┘
                                         │ new outbound citations
                                         └──────────────▶ back to FRONTIER (bounded BFS)

    The orchestration loop (Component 6) is the only genuinely new control flow. Everything below the GATE already exists.

    4. Component 1 — Jurisdiction taxonomy + canonical identifiers¶

    Today canonical_key is a flat prefix:citation string (dgcl:145, securities-act:4(a)(2), sec-rule:506(b), term:company) and jurisdiction is implicit in the prefix. To key authorities we have never seen, add two classification dimensions and a queryable namespace table — without breaking existing keys (they remain valid and become rows in the new table).

    4.1 Two new classification fields¶

    • jurisdiction — a hierarchical, dotless code: us-federal, us-de, us-tx, us-ca, us-ca-san-francisco, us-guam. Hierarchy is by - prefix (us-ca is an ancestor of us-ca-san-francisco), enabling "all California authorities" rollups without a join table.
    • authority_type — controlled vocabulary: statute | regulation | admin-rule | municipal-ordinance | case | constitution | court-rule | guidance | treaty.

    These are added to CorpusReference (indexed, nullable for back-compat) and are the routing keys providers claim on — not the opaque canonical_key prefix, which providers must never parse.

    4.2 AuthorityNamespace (the body-of-law / routing unit)¶

    One row per body of law, generalizing today's scattered alias storage into a single queryable table:

    field purpose
    prefix (unique) canonical_key prefix, e.g. tx-boc, cfr-40, exchange-act
    display_name "Texas Business Organizations Code"
    jurisdiction / authority_type classification (Component 1.1)
    aliases (JSON) surface forms seen in text; feeds the extractor registry
    provider provider id that handles this namespace (once known)
    source_root_url / license where the body of law lives; its license
    discovery_state UNKNOWN → LOCATABLE → LOCATED → INGESTED / UNLOCATED / BLOCKED_LICENSE
    candidate_sources (JSON) located URLs + detected license + reject reason

    authority_alias_registry(user) (authorities.py:59) is refactored to read aliases from AuthorityNamespace (visibility-scoped: a namespace contributes aliases only if its authority corpus is visible, or it is a global/public namespace) and keep reading Document.custom_meta.authority_aliases as a sync source during migration. The static AUTHORITY_PREFIX dict seeds the table once via data migration; the dict stays as the bootstrap fallback so the engine is importable without DB access (tests, cold start).

    4.3 Key equivalence (closes the USC↔act-section gap)¶

    A statute is cited two ways that must dedupe to one authority: "Securities Exchange Act Section 10(b)" (exchange-act:10(b)) and "15 U.S.C. § 78j(b)" (usc-15:78j(b)) are the same law. A small AuthorityKeyEquivalence(key_a, key_b, source) table records these; a canonicalization helper picks a primary. The USCodeProvider (Component 4) populates equivalences from USLM identifiers, which is exactly the fix the versioning note already recommended ("the USLM identifiers also solve the USC→act-section mapping gap", reference-web-versioning.md:62). Equivalence is consulted in find_authority_target and the frontier dedupe so the two surface forms resolve to one ingested document.

    5. Component 2 — Open-vocabulary detection¶

    Layered extraction. Each layer emits the existing Candidate dataclass (extractor.py:18), extended with optional jurisdiction, authority_type, and detection_tier / detection_confidence. Reconciliation merges layers before resolution.

    5.1 Tier 1 — registry grammars (unchanged)¶

    The shipped ReferenceExtractor grammars, verbatim. Highest precision, confidence = 1.0, detection_tier = "registry". Zero behavior change when Tier 2 is off — protects every existing test and corpus.

    5.2 Tier 2a — generic citation-shape grammars (deterministic)¶

    Shape-based regexes that match citation form without knowing the body of law. New module enrichment/grammars.py. Each emits a provisional canonical_key, a minted/looked-up prefix, and jurisdiction/type guesses:

    form example provisional key jurisdiction / type
    US Code 15 U.S.C. § 78j(b) usc-15:78j(b) us-federal / statute
    CFR 40 C.F.R. § 261.4 cfr-40:261.4 us-federal / regulation
    Fed. Register 88 Fed. Reg. 1722 fedreg:88.1722 us-federal / admin-rule
    Public Law Pub. L. No. 117-58 publ:117-58 us-federal / statute
    Statutes at Large 135 Stat. 429 stat:135.429 us-federal / statute
    State code (named) Tex. Bus. Orgs. Code § 21.401 tx-boc:21.401 us-tx / statute
    State rev. stat. Cal. Corp. Code § 300 ca-corp:300 us-ca / statute
    Municipal S.F. Police Code art. 38 sf-police:38 us-ca-san-francisco / municipal-ordinance
    Bare Act the Bank Holding Company Act of 1956 act:bank-holding-company-1956 us-federal? / statute

    State/municipal forms lean on a curated abbreviation table (public Bluebook-style jurisdiction + reporter/code abbreviations — facts, not protected expression) mapping Tex. Bus. Orgs. Code → (tx-boc, us-tx, statute). The table is data, extensible without code change, seeded from public jurisdiction/abbreviation tables. confidence ≈ 0.9 for structured numeric cites, lower for bare Acts (no section ⇒ a whole-body authority, marked section = None).

    5.3 Tier 2b — LLM extraction pass (recall)¶

    A structured-output LLM pass over chunked document text catches prose and obscure references the grammars miss ("the Commission's rules under the Investment Advisers Act", "the Guam Administrative Adjudication Law"). Reuses the existing LLM framework (opencontractserver/llms/), a pydantic-ai agent created with instructions= not system_prompt= (project pitfall #14 / memory) returning, per span: {raw_text, char_span, jurisdiction, authority_type, normalized_citation, confidence}.

    Controls (precision is the risk):

    • Off by default; enabled per run via the discovery tool / CorpusAction config.
    • Results below a confidence floor go to a review bucket (persisted with a needs_review flag), never auto-promoted to mentions.
    • The model is given only the document text, never told "find citations to X" (no leading), and every returned span is verified to exist at the claimed offsets before persistence (reject hallucinated spans).
    • detection_tier = "llm", confidence as returned, dampened by a calibration factor.

    5.4 Reconciliation¶

    A reconcile(candidates) step (new, in the service): group by span overlap; on overlap keep the highest-precedence layer (registry > grammar > llm) and take the max confidence; dedupe identical (canonical_key, span) pairs; apply key equivalence (Component 4.3) so exchange-act:10(b) and usc-15:78j(b) collapse. Output feeds the existing ReferenceResolver unchanged — law candidates still resolve to STATUS_EXTERNAL stubs; the new classification rides along in normalized_data and the new columns.

    6. Component 3 — The frontier¶

    Generalize wanted_authorities() (corpus_reference_service.py:29) from a computed aggregate into a durable, rankable queue.

    6.1 AuthorityFrontier model (one row per wanted section key)¶

    field purpose
    canonical_key (indexed) e.g. tx-boc:21.401 (section granularity, matching the bootstrapper's one-doc-per-section unit)
    namespace (FK → AuthorityNamespace) routing / body-of-law
    jurisdiction / authority_type denormalized for cheap filtering
    mention_count / key_count / corpus_count demand (recomputed from CorpusReference)
    discovery_state UNKNOWN → LOCATABLE → LOCATED → INGESTED / UNLOCATED / BLOCKED_LICENSE / PENDING_APPROVAL / FAILED
    depth hops from a seed (filing) corpus; 0 = directly cited
    confidence best detection confidence for this key
    provider / candidate_sources (JSON) / last_error routing + audit
    ingested_document (FK, null) the authority doc once materialized
    created_by_analysis (FK) provenance

    Rank = mention_count × confidence with a depth penalty (a one-hop authority cited 80× outranks a three-hop authority cited twice). A demand floor (min mentions, configurable) keeps one-off cites out of the crawl.

    The frontier is corpus-scoped for queries (for_corpus) but rows are keyed by canonical_key so the same authority wanted by many corpora is one ingest target — the cross-corpus dedupe the canonical_key index already anticipates. wanted_authorities() becomes a thin read over this table (back-compatible shape) plus a recompute method invoked at end of each enrichment apply.

    7. Component 4 — Authority source providers¶

    A registry mirroring the shipped pluggable-pipeline pattern (PipelineComponentBase: ABC + ClassVar metadata + nested Settings dataclass + auto-discovery registry, opencontractserver/pipeline/). New package opencontractserver/enrichment/providers/.

    7.1 BaseAuthoritySourceProvider¶

    class BaseAuthoritySourceProvider(ABC):
    title: str
    description: str
    jurisdictions: ClassVar[list[str]]      # claim hints, e.g. ["us-federal"]
    authority_types: ClassVar[list[str]]    # e.g. ["statute"]
    license: ClassVar[str]                  # "public-domain", "us-gov", ...
    trust: ClassVar[int]                    # tie-break rank; official > aggregator
    class Settings: ...                     # API keys/URLs via PipelineSetting

    @abstractmethod
    def can_handle(self, item: FrontierItem) -> float: ...      # 0..1 claim
    @abstractmethod
    def locate(self, item: FrontierItem) -> SourceLocation | None: ...
    @abstractmethod
    def fetch(self, loc: SourceLocation) -> AuthorityFetchResult: ...

    FrontierItem is the in-memory view of an AuthorityFrontier row (Component 6.1) — canonical_key, namespace, jurisdiction, authority_type, demand.

    AuthorityFetchResult carries sections: list[AuthoritySection] (the exact shape bootstrap_authority_corpus already consumes — authorities.py:40), plus source_url, license, retrieved_at. Provider selection: highest can_handle, ties broken by trust. locate/fetch are separated so the frontier can show LOCATED (URL found) distinctly from INGESTED, and so a located-but-license-blocked source is recorded without fetching full text.

    7.2 Concrete providers (public-domain only, per licensing decision)¶

    provider source covers license
    USCodeProvider OLRC USLM XML bulk (uscode.house.gov) US Code titles; emits USLM ids → key equivalence public domain
    CFRProvider eCFR REST API (ecfr.gov) Code of Federal Regulations, all titles/agencies public domain
    FederalRegisterProvider federalregister.gov API rules / notices by FR citation public domain
    StateCodeProvider Open States bulk + official legislature sites state statutes (pluggable per state; seed high-demand states) varies — see §9
    CourtListenerProvider CourtListener API (off by default) opinions public domain (opinions)
    AgenticWebLocatorProvider LLM + web search + fetch anything no structured provider claims per-source, gated

    Structured providers convert their native format (USLM XML, eCFR JSON) into AuthoritySection lists and hand off to the existing bootstrap_authority_corpus — they add no persistence code. eCFR and OLRC are exactly the sources the versioning note already endorsed (reference-web-versioning.md:60).

    7.3 AgenticWebLocatorProvider — the "don't know where to find it" path¶

    Lowest can_handle (claims only what nothing else does). An agent with web-search + URL-fetch tools, given only the normalized citation + jurisdiction/type (never the citing document's text — see §10 privacy), locates candidate sources and extracts the section text. It does not ingest; it returns candidates to the gate (Component 5). This is what lets the system reach state, municipal, tribal, territorial, and obscure-agency law without a hand-built integration per source.

    8. Component 5 — Verify + license gate¶

    Every agentic / low-confidence / non-allowlisted result passes the gate before ingest. Structured-provider results from allowlisted domains may skip straight to ingest when confidence is high.

    Checks

    1. Citation match — the fetched text's own heading/identifier matches the requested canonical_key (e.g. the page's USLM id or heading is §21.401). Deterministic where possible; LLM-assisted for prose.
    2. Source trust — domain on the public-domain government allowlist (§9).
    3. License — declared/detected license is in the allowed set.
    4. Sanity — non-empty, length within bounds, parses as the claimed type.

    Outcomes (all non-silent)

    • Pass + trusted + confident → ingest via bootstrap_authority_corpus; frontier → INGESTED.
    • BLOCKED_LICENSE — source(s) found but none clear the allowlist. The item stays in the frontier and governance graph as a visible node with a distinct state; candidate_sources records each URL, its detected license, and the reject reason; routes to the human-approval queue. A human may supply a compliant source or override case-by-case (override logged with who/when/why and stamps the non-PD license into the doc's custom_meta). Public-domain is the default, not a hard wall.
    • UNLOCATED — no source found at all. Visible terminal state, retryable.
    • PENDING_APPROVAL — passed checks but below the auto-ingest confidence threshold; awaits human confirm.

    The crawl orchestration logs every blocked/unlocated authority (no silent truncation — project rule) and the per-run Analysis summary reports counts: {ingested, blocked_license, unlocated, pending_approval, failed}.

    9. Licensing posture (cross-cutting)¶

    Default: public-domain government primary sources only. Allowlist (domains + license tags) lives in enrichment/licensing.py:

    • Allowed: uscode.house.gov (OLRC/USLM), ecfr.gov, federalregister.gov, govinfo.gov, official *.gov state legislature/agency domains, courtlistener.com (opinions only). License tags: public-domain, us-gov-work, edict-of-government.
    • Excluded by default: Cornell LII (CC BY-NC-SA — non-commercial; project memory already flags this), commercial aggregators, anything without a clear public-domain/edict basis.

    State & municipal nuance (called out, not hand-waved): the text of the law is public domain / an edict of government (cf. Georgia v. Public.Resource.Org, 2020), but some official compilers (Municode, American Legal Publishing) assert copyright over their compilation/annotations. The gate distinguishes the public-domain statutory text from protected editorial matter; when only a protected-compilation source exists, the item goes BLOCKED_LICENSE with the source recorded — surfaced, never dropped. Every ingested authority doc stores license, source_url, retrieved_at in custom_meta (extends the existing stamp in authorities.py:_stamp_key).

    10. Component 6 — Recursive frontier expansion (the crawl)¶

    A bounded BFS Celery orchestration tying the pieces together. New task module enrichment/crawl.py, dispatched like the existing enrichment analyzer (ENRICHMENT_ANALYZER_TASK) and installable as a CorpusAction so the graph keeps growing as documents are added (mirrors the shipped add_document action).

    seed:   open-vocab enrichment on corpus → recompute frontier (depth 0)
loop until (frontier empty | depth ≥ MAX_DEPTH | budget exhausted
            | no item ≥ DEMAND_FLOOR):
    item     = frontier.pop_top()                 # rank, demand floor
    provider = registry.select(item)              # may be AgenticWeb
    located  = provider.locate(item)              # → LOCATED | UNLOCATED
    result   = provider.fetch(located)
    if gate.verify(result, item):                 # §8
        bootstrap_authority_corpus(result.sections, …)   # REUSED → auto-relink
        re_extract(new_authority_docs)            # surfaces THEIR citations
        frontier.add(new_citations, depth = item.depth + 1)   # expansion
        item.state = INGESTED
    else:
        item.state ∈ {BLOCKED_LICENSE, UNLOCATED, PENDING_APPROVAL}  # visible
    log(item.state); analysis.tally(item.state)

    Bounds (all configurable; all surfaced in the run summary):

    • MAX_DEPTH — hops from the seed corpus (default 2). Depth 0 = directly cited; depth 1 = cited by an ingested authority; etc.
    • Token/$ budget — the orchestration is budget-aware; agentic locate and Tier-2b LLM calls draw it down; the loop stops cleanly when exhausted.
    • Demand floor — skip authorities below N mentions (don't chase one-offs).
    • Per-jurisdiction caps — bound a single crawl from exploding into, say, all 50 state codes at once.

    bootstrap_authority_corpus already (a) version-ups idempotently and (b) calls relink_corpora_for_keys to upgrade EXTERNAL→RESOLVED across every citing corpus. So each successful ingest automatically lights up the new authority across the whole reference web; the crawl only adds the recursion and the bounds. Re-running a crawl is idempotent: already-INGESTED keys are skipped, new mentions found in newly-ingested authority text extend the frontier.

    11. Data-model changes (summary)¶

    All additive; migrations are back-compatible.

    • CorpusReference (annotations/models.py:1901): add indexed jurisdiction, authority_type, detection_tier, detection_confidence. The _require_type_label_agreement save guard and idempotency constraints are untouched.
    • AuthorityNamespace — new (Component 4.2). Data migration seeds it from AUTHORITY_PREFIX + existing authority-corpus aliases.
    • AuthorityKeyEquivalence — new (Component 4.3).
    • AuthorityFrontier — new (Component 6.1).
    • Provider config rides the existing PipelineSettings singleton (secrets via PipelineSetting env vars), no new settings table.

    12. Surfaces¶

    Agent tools (llms/tools/core_tools/corpus_references.py, async twins as today), each with corpus_id/creator_id injected and hidden from the LLM:

    • discover_authorities(corpus_id, *, tiers=["registry","grammar"], llm=False) — scan with open-vocabulary detection on; read-only inventory of newly detectable authorities by jurisdiction/type. Extends scan_corpus_references.
    • list_authority_frontier(corpus_id) — the ranked frontier with discovery_state (supersedes / wraps list_wanted_authorities).
    • locate_authority(canonical_key) — run providers' locate for one key, return candidate sources (no ingest).
    • crawl_authorities(corpus_id, *, max_depth, budget, demand_floor) — approval-gated; runs Component 6. Returns the {ingested, blocked_license, unlocated, …} tally.

    GraphQL — extend WantedAuthorityType with jurisdiction, authority_type, discovery_state; add a frontier query. All resolvers go through the service layer (CorpusReferenceService / a new AuthorityFrontierService) — no inline Tier-0 permission calls in config/graphql/ (project invariant E001).

    Governance graph (governance_graph_service.py) — node payloads gain jurisdiction + authority_type (frontend colors/shapes by regime) and ghost nodes gain discovery_state so UNKNOWN / LOCATED / BLOCKED_LICENSE authorities are visually distinct — the "weird ones" become legible at a glance. Existing node kinds (primary/exhibit/statute/external) and edge types are preserved; this is additive.

    13. Security & permissions¶

    • Visibility scoping unchanged. Frontier and namespace reads derive visibility from corpus visibility via services (the CorpusReference model). find_authority_target keeps its visible_to_user + is_current filter. Ingested public authority corpora are made public via the existing make_public path so they resolve for everyone.
    • SSRF defense on every fetch. locate/fetch and the agentic tool route through one hardened HTTP client: domain allowlist enforced after DNS resolution, private/loopback/link-local IP ranges blocked, redirects re-validated against the allowlist, response size + timeout caps, no arbitrary schemes. Lives in enrichment/net.py; unit-tested against redirect-to-internal and DNS-rebind cases.
    • Privacy of the locate path (§7.3). The agentic locator receives only the normalized citation string + jurisdiction/type — never the citing document's text. External locate is opt-in per corpus (a corpus setting / explicit tool consent), because issuing a web search derived from a private corpus reveals that the corpus cites that authority. Structured-provider fetches (citation key → public gov endpoint) are lower-risk but still gated by the same opt-in for non-public corpora.
    • Agent tool fault model unchanged: operational errors return strings to the LLM; PermissionError / ToolConfirmationRequired propagate (issue #820). crawl_authorities is requires_approval.

    14. Testing strategy (TDD, project conventions)¶

    • Grammars (Tier 2a) — a golden cross-jurisdiction citation corpus (federal USC/CFR/FedReg/PubL, ≥5 state forms, ≥2 municipal, bare Acts) with expected (canonical_key, jurisdiction, authority_type); precision/recall assertions; negative cases (prose that must not match).
    • LLM pass (Tier 2b) — mocked structured outputs; assert hallucinated-span rejection, confidence bucketing, and that instructions= is used.
    • Reconciliation — registry > grammar > llm precedence; equivalence collapse (exchange-act:10(b) ≡ usc-15:78j(b)).
    • Providers — against recorded fixtures (saved USLM XML / eCFR JSON); never hit live government APIs in CI. One contract test per provider that its output AuthoritySections satisfy bootstrap_authority_corpus.
    • Gate — must reject mismatched citation, non-allowlisted domain, non-PD license, and empty/garbage text; assert BLOCKED_LICENSE / UNLOCATED are produced and recorded (never dropped).
    • SSRF client — redirect-to-internal, private-IP, DNS-rebind blocked.
    • Crawl bounds — depth, budget, demand-floor, and per-jurisdiction caps each provably terminate the loop; blocked/unlocated authorities are logged and tallied.
    • Idempotency — re-crawl creates zero duplicate authorities/refs (rerun the shipped engine's idempotency assertions over the expanded surface).
    • Permissions — frontier/namespace reads scoped to visible corpora; private authority resolves only for authorized users (extends the shipped relink_corpora_for_keys per-corpus-visibility tests).

    Per project process: backend pre-commit + targeted test subsets locally, full suite in CI; one changelog.d/<slug>.<type>.md fragment per phase.

    15. Phasing (feature branch + per-phase tracking issues)¶

    This is a multi-phase initiative → a feature branch with a PR and per-phase tracking issues (project convention), not direct-to-main. Each phase is independently shippable and valuable.

    phase deliverable value
    0 — Taxonomy foundation jurisdiction/authority_type on CorpusReference; AuthorityNamespace + data migration from AUTHORITY_PREFIX; authority_alias_registry reads the table de-risks everything; no behavior change
    1 — Tier 2a detection generic shape grammars + abbreviation table; reconciliation; discover_authorities tool finds the weird ones (structured cites) — deterministic, cheap, highest leverage
    2 — Tier 2b detection LLM extraction pass + review bucket recall for prose / obscure-agency references
    3 — Frontier + structured providers AuthorityFrontier; provider registry; USCode/CFR/FedRegister providers; key equivalence auto-locate + ingest for federal/regulatory
    4 — Agentic locate + gate AgenticWebLocatorProvider; verify/license gate; BLOCKED_LICENSE/UNLOCATED states; SSRF client; human-approval queue reach for unknown sources without per-source code
    5 — Recursive crawl bounded BFS orchestration; CorpusAction; governance-graph regime coloring + discovery_state the self-expanding reference web

    Phase 1 alone answers the core request for the large class of authorities that are cited in a recognizable form. Phases 3–5 deliver the autonomous locate-and-ingest crawl for the genuinely unknown.

    16. Risks & open questions¶

    • Tier-2b precision. LLM extraction can hallucinate citations. Mitigated by span-existence verification, confidence flooring, review bucket, off-by- default. Open: calibration factor per model; revisit after Phase 2 data.
    • Provisional-key churn. A minted key (tx-boc:21.401) that later proves wrong (bad abbreviation mapping) needs reconciliation. Mitigation: keys are provisional until a provider confirms via locate; the equivalence table absorbs corrections; abbreviation table is data, fixable without migration.
    • State-source breadth. 50 states × multiple codes is a long tail. StateCodeProvider is pluggable per state; we seed high-demand states and let AgenticWebLocatorProvider cover the rest (gated). We do not block the design on exhaustive state coverage.
    • Crawl cost. Recursive + agentic + LLM can be expensive. Hard bounds (depth/budget/demand/jurisdiction) + approval gating + per-run tallies keep it controlled and observable.
    • Open question: should depth-1+ authorities (a statute cited by a statute we ingested, but not by the user's filings) join the user's governance graph, or only the shared authority library? Proposed: ingest into the shared authority library always; surface in a corpus's graph only when that corpus (transitively at depth ≤ 1) cites it — keeps each corpus's graph relevant. ```
