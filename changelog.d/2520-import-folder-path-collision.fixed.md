- **Importing into a folder no longer replaces a same-named document in a different folder** (issue #2520, reported in #2515). `Corpus.import_content` (`corpuses/models.py`) ignored `folder` when generating a default path, so every file landed at `/documents/<filename>`, and `import_document` then treated the second file as a new version of the first: the first document disappeared from its folder and two unrelated files shared a version tree. The single-document upload service (`document_imports/services.py::import_document_for_user`) hit this directly, and the agent tool (`llms/tools/core_tools/text_document_import.py`) hit it through its own title-derived path. Both now use `CorpusPathService.resolve_folder_import_path` (`corpuses/services/paths.py`), which generates `/<folder path>/<filename>`. Re-importing into the same folder is still a new version, including for documents already stored at a legacy `/documents/<filename>` path, so no data migration is needed. Impact: new foldered imports get folder-derived paths, which folder renames also keep in sync. Imports with no folder are unchanged, and documents already affected are not repaired automatically; their earlier version is still in the version history.
