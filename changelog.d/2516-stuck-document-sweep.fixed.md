- **Bulk uploads no longer leave healthy documents permanently `FAILED`** (issue #2516). `reconcile_stuck_documents` measured its stale window from upload (`documents/signals.py::process_doc_on_create_atomic`) but only considers `PROCESSING` documents, so a document that queued past `DOCUMENT_PROCESSING_STALE_MINUTES` was reclaimed within one beat of `ingest_doc` picking it up. `ingest_doc` (`tasks/doc_tasks.py`) now restarts `processing_started` on the `PENDING` → `PROCESSING` transition. It deliberately does not restart it on a worker-lost redelivery, which also arrives with `retries == 0`, so a document that keeps killing its worker is still reclaimed. Separately, `remap_pending_annotations` and `set_doc_lock_state` queue behind the whole `doc_parse` backlog, so a parsed document can still outlive the window; `set_doc_lock_state` now overturns a sweep verdict (matched on `constants/document_processing.py::STUCK_DOCUMENT_SWEEP_ERROR_PREFIX`), clears the error and completes the document, including firing its corpus actions. Genuine failures stay `FAILED` and locked. Impact: `processing_started` now means when ingest began rather than upload time, so the ingestion-admin duration no longer includes queue wait. A swept document's creator can still receive a failure notification before it recovers.
