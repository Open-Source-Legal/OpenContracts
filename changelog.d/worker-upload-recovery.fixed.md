Worker uploads accept durable client keys, return the same receipt for identical replays, and support receipt lookup, readiness status, and repair across token rotation. Processing uses fenced transactions and bounded retries; the remote CLI reconciles lost responses, preserves identity after rejected replays, and retries existing receipts without repeating preparation. Exhausted receipts release their staged source, and identical keyed submissions serialize on a per-key advisory lock instead of an account-wide row lock.
