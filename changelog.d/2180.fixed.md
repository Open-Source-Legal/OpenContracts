- **Deep research: cite supporting passages, not section headers (#2180).** Deep-research reports were anchoring footnotes to structural section-header annotations (e.g. `raw_text` `"ITEM 1A. RISK FACTORS"`) rather than the passage whose words support the sentence, because `similarity_search` returns header and body annotations interchangeably and nothing required a citation to be substantive. Fixes:
  - `opencontractserver/research/constants.py`: added a `## Citation discipline` section to `build_deep_research_system_prompt` instructing the agent to cite the operative passage, never a bare heading, and to re-query with the claim's specific language (only `similarity_search` results are citable — `search_exact_text_as_sources` results are not). Added `RESEARCH_HEADER_ANNOTATION_LABELS` + `normalize_annotation_label_text` — a parser-agnostic header-label predicate (Docling `section_header` and LlamaParse `Section Header` both normalize to the same key; length is deliberately not used).
  - `opencontractserver/research/services/research_reports.py`: added `ResearchReportService.header_like_citation_ids` (flags `structural` annotations whose normalized label is a heading). `finalize` now strips header anchors that slip into a `<cite>` tag so no footnote ever points at a bare heading (silent defence-in-depth, mirroring the existing retrieved-id intersection).
  - `opencontractserver/tasks/research_tasks.py`: the `record_finding` closure now rejects a finding whose every citation is a section header, returning an actionable message naming the offending anchors so the agent re-anchors while it still has budget.
