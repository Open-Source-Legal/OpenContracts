- Bumped the frontend toolchain from Node 20 to Node 24 everywhere it is pinned: CI (`.github/workflows/frontend.yml`, `frontend-e2e.yml`, `frontend-e2e-extract.yml`, `frontend-e2e-websocket.yml`, `screenshots.yml`), the production image (`frontend/Dockerfile`, now `node:24-alpine`) and `frontend/.nvmrc` (was a stale `v16.19.1`). Node 20 reached end-of-life in April 2026. The `@graphql-tools/executor-legacy-ws` 1.1.21 → 1.1.37 security bump (GHSA-6fw5-9hq8-w87g, GHSA-434m-5hcj-pxf3, GHSA-mp66-8ww2-pcwm) pulls in `@whatwg-node/promise-helpers@2`, which declares `engines.node >=22.15.0`, so `yarn install --frozen-lockfile` aborted on Node 20 (`error @whatwg-node/promise-helpers@2.0.0: The engine "node" is incompatible with this module`). Every `executor-legacy-ws` release that carries the fixes (>=1.1.35) depends on `@graphql-tools/utils@12`, so no lockfile-only resolution exists; the package is a dev-only transitive of `@graphql-codegen/cli` and never ships in the bundle.
- `frontend/package.json` now declares `engines.node >=22.15.0`, so a contributor on an older Node gets a clear top-level `yarn install` error instead of one attributed to a transitive package. Removed `frontend/.github/workflows/playwright.yml`, Playwright boilerplate from the original Vite switch that GitHub never ran (workflows only execute from the repository-root `.github/`) and nothing referenced.
