- Reject inactive accounts when restoring login sessions. Django admin sessions created by the Auth0 token login (`config/admin_auth/backends.py::Auth0AdminBackend`) previously kept working after deactivation because the backend's `get_user` skipped the `is_active` check; the override is removed so the inherited `ModelBackend.get_user` applies. The header-only JWT backends (`config/jwt_auth/backends.py`, `config/graphql_auth0_auth/backends.py`) never create sessions today, but their `get_user` now shares `config/jwt_auth/shortcuts.py::get_active_user` as defense-in-depth. Lookups remain a single query.
