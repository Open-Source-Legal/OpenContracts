- Pinned `graphql-core>=3.2,<3.3` in `requirements/base.txt`. It was only a transitive dependency of `strawberry-graphql` (which allows `<3.4`), so fresh installs picked up graphql-core 3.3.0. 3.3 changed `graphql.execution.collect_fields` (new `operation`/`FragmentDetails` signature, `CollectedFields` NamedTuple return), which breaks the scoped-automation selection check in `config/graphql/automation.py::_check` at runtime and fails mypy (`automation.py:151`, `opencontractserver/tests/test_coverage_core_scalars.py:45`). Moving to 3.3 needs a deliberate port of `_check`.
