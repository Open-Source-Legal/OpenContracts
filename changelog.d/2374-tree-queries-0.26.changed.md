- `requirements/base.txt` — `django-tree-queries` 0.25.1 → 0.26.1. **Behavior change:** `Corpus.objects` and `CorpusFolder.objects` are `PermissionedTreeQuerySet.as_manager(with_tree_fields=True)`, and up to 0.25 the tree compiler's depth-first `extra_order_by` silently overrode every explicit `.order_by()` on them. From 0.26 an explicit `.order_by()` wins. Corpus lists that already asked for an order now get it: for example, `discovery/views.py`'s recent public corpuses (`-created`) and the `search_queries.py` corpus results (`-modified`) were really in tree order (effectively pk) before. Querysets without an explicit ordering keep depth-first order. The compiler now also writes `tree_ordering` into `query.order_by` when a queryset is compiled, which is why `test_visibility_managers.py::test_superuser_has_no_blanket_access_queryset` now checks `query.order_by` before evaluating the queryset.
