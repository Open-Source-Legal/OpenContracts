- `EnrichmentWriter._ensure_corpus_reference()` (`opencontractserver/enrichment/writer.py`): a `CorpusReference` row persisted as `UNRESOLVED` (its target couldn't be found at write time) was never upgraded to `RESOLVED` by a later run that *does* find the target — `get_or_create`'s lookup key (`source_annotation`, `reference_type`, `canonical_key`) doesn't include the resolution outcome, so a re-apply silently re-fetched the stale unresolved row instead of updating it. This affected both `EnrichmentService` (general authority/law-reference discovery) and `CustomsRulingCitationService`, and meant an in-memory "N resolved" count could diverge from what actually persisted (a run could report resolutions with zero new/updated `CorpusReference` rows to show for it). Added a forward-only heal — mirroring the existing jurisdiction/authority_type heal in the same method — that upgrades `target_document_id`/`target_annotation_id`/`resolution_status`/`confidence`/`normalized_data` on an existing `UNRESOLVED` row once a later run resolves it; an already-`RESOLVED` row is never downgraded. New `WriteResult.references_resolved` / `EnrichmentSummary.references_resolved` counters surface how many existing rows were healed, distinct from `references_created` (brand-new rows).
